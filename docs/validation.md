## 已确认的问题与修复

**原生捕获缺少呈现同步。** 旧流程在第一个原生 API 成功帧上直接保存，
没有确认该帧包含本次 Flutter 页面。框架 `endOfFrame` 与 Windows 捕获队列不是
同一个完成条件。现在测试入口绘制每次请求独有的 24 位序号标记，WGC 从真实
HWND 像素中读到匹配标记才返回，最多等待 10 秒。录屏启动也使用这个条件；
录屏期间允许并行截图推进序号，并继续验证标记存在。不会拼接 App 图与标题栏。

冷启动回归会故意请求尚未绘制的序号，确认旧帧被拒绝，待应用实际绘制该序号
才完成；另一个永不呈现的序号必须超时，且不能生成冒充成功的 PNG。
历史白屏的具体 OS/GPU 触发条件在本轮冷启动及受控遮挡对照中未重新出现，
因此不能认定为某个已证实的 Flutter 引擎或 GPU 缺陷。修复的是已确认的同步缺口，
新流程会对无法呈现的内容明确失败。

**不激活与后台层级不同。** 原先 `SW_SHOWNOACTIVATE` 仍可能把未激活的窗口
放到用户已激活窗口上方，再点原本已激活的窗口不一定重新排列 Z-order。
首次显示改为 `SetWindowPos(HWND_BOTTOM, SWP_NOACTIVATE | SWP_SHOWWINDOW)`，
原子地建立底部层级。未设 topmost，后续用户主动激活仍保持正常。

**副屏位置与 DPI。** 默认自动选最大副屏工作区，无副屏时回主屏；按 DPI 和
工作区尺寸居中，避开任务栏。修复了桌面原点使用无符号数、且被重复 DPI 缩放
的问题。本机副屏位于主屏左侧，工作区为 `(-2160, 0)–(0, 3768)`，
实际窗口为 `(-2040, 1344)–(-120, 2424)`，完整位于副屏工作区内。
`start primary` 可改用主屏，仍从后台层级显示。

**App 截图原先只有 1× logical pixel。** 现在按实际视图 DPI（本机 1.5）保存
原始 PNG。捕获边界移到 Navigator 外，包含 Flutter 弹窗与 Overlay。
录屏新增原尺寸 FFV1/BGRA 无损母版，MP4 只作为浏览副本。
